# Amazon 评价/变狗检测工具 — 开源方案调研

> 调研日期：2026-08-14
> 调研目标：为「批量导入 Amazon 评价链接 → 内置浏览器访问 → 判断评价是否还在 / 是否变狗 / 几星」的纳米项目寻找可二开的开源方案。
> 数据来源：GitHub API（star / 最后 push / license / README / commit 记录）。

---

## 一、TL;DR（结论先行）

1. **没有任何一个现成项目做「批量检测评价链接是否变狗 + 评价是否还在 + 星级」这件事。** 这是空白市场，必须自己组合。
2. 候选仓库绝大多数是 **「爬取工具」（scrape，一次性拉数据）**，不是 **「监控工具」（monitor，定期检测状态变化）**。真正带定时轮询监控架构的只有 `SpikeHD/AmazonMonitor`，但它监控的是价格/补货，**不监控评价/变狗**。
3. **最值得拉进 `code/` 的**：`omkarcloud/botasaurus`（反检测底座，免费、活跃）。业务/UI 层没有"改改就能用"的，需自己写。
4. **不要被高 star 误导**：`oxylabs/amazon-scraper`(3.3k★)、`ScrapingBee/amazon-review-scraper`(182★)、`omkarcloud/amazon-scraper`(227★) 都是 **付费 SaaS API 的示例代码**，内网部署要持续花钱买额度。

## 三、核心洞察：爬取 vs 监控

这是本次调研最重要的判断——**搞清两个概念**：

| | 爬取 (Scrape) | 监控 (Monitor) |
|---|--------------|---------------|
| 行为 | 一次性拉数据 | 定时反复检查 |
| 关注 | 数据内容（评价说了啥、价格多少） | 状态变化（还在不在、是否消失） |
| 典型形态 | 抓 1000 条评论存 JSON | 每隔 N 分钟看一眼，变了就通知 |
| 本项目需求 | ❌ 不是这个 | ✅ **正是这个** |

**结论**：上面 12 个仓库里，11 个是「爬取」，只有 `SpikeHD/AmazonMonitor` 是「监控」，而它又不监控评价/变狗。所以**没有可直接拿来用的**。

## 四、逐个深挖（重点仓库）

### ⭐ 1. omkarcloud/botasaurus — 反检测底座（强烈推荐）

- **定位**：The All in One Framework to Build Undefeatable Scrapers（反检测爬虫框架）
- **维护**：🟢 最近 commit 2026-07-26，持续在推（autopublish + fixes）
- **免费**：✅ MIT，纯本地框架，不依赖付费服务
- **关键能力**（来自 README）：
  - 反检测浏览器（绕 Cloudflare / Datadome）
  - Cloudflare Turnstile / Captcha 处理
  - 代理轮换（传 list 自动轮换）
  - Captcha 自动求解（集成 CapSolver，**打码本身付费**）
  - 并行化 / 浏览器 profile / 扩展
  - 可打包桌面应用（Win/macOS/Linux）
- **Amazon 关联**：README 官方示例项目就有 **"Amazon Invoice PDF Extractor"**，说明对 Amazon 场景友好
- **坑**：README 明确警告 **headless 模式会被 Cloudflare/Datadome 识别**，对 Amazon 这种强反爬建议 headed 模式 + 代理 + 可能的打码服务
- **二开价值**：⭐⭐⭐⭐⭐ 作为浏览器访问层底座，无可替代

### ⭐ 2. SpikeHD/AmazonMonitor — 监控架构范本（抄架构）

- **定位**：自托管 Discord bot，监控 Amazon 价格下降和补货
- **维护**：🟢 2026-05，支持 Discord.js v14 + TS
- **免费**：✅ 自托管（需 Discord bot token，可选代理列表）
- **是真正的"监控"** ✅：核心配置 `minutes_per_check`（轮询周期）+ `seconds_between_check`（每条间隔）+ 缓存对比检测变化
- **监控指标**：价格下降、补货（restock）。**不监控** listing 失效/变狗/评价删除
- **形态问题**：Discord bot，**不是 Web**。跟"宝塔 + 网站"诉求不匹配
- **二开价值**：⭐⭐⭐⭐ 它的「定时轮询 + 状态对比 + 变化通知」架构是监控类最好范本，值得抄；但要从 TS/Discord 改写成 Python/Web，工作量中等

### 3. mohitrock850/-Amazon-Scraper-Dashboard — 形态最像（但 0★ 要重写）

- **定位**：Python + Streamlit + Selenium(stealth) 的 Amazon 抓取看板
- **维护**：🟡 2025-09，**0 star 单人项目**，教学性质
- **免费**：✅（Selenium 本地，selenium-stealth）
- **已实现**：
  - `scraping.py`：反检测无头浏览器 + Amazon 产品页解析（**已提取星级 `RatingText`、评价数 `TotalReviews`、平均星 `AverageRating`、星级分布 `RatingsBreakdown`**）
  - `dashboard.py`：Streamlit 页面（输入关键词 → 抓取 → 卡片展示）
  - 多选择器容错 `find_with_fallbacks()`，写法稳健
- **致命短板**：是「**搜索关键词 → 抓取**」模式，不是「**批量导入链接 → 检测**」模式。要重写 `main()` + 加变狗判定
- **二开价值**：⭐⭐⭐ 作为 Streamlit UI 范本 + Amazon DOM 选择器速查很有用；但 main 逻辑要重写，不能"改改就用"

### 4. philipperemy/amazon-reviews-scraper — 评价爬取参考

- **定位**：多语言 Amazon 评价抓取，存 JSON
- **维护**：🟡 2024-11 停滞
- **免费**：✅ 但 README **明确警告 "Amazon bans after 5000 queries on average"**，需 VPN（推荐 ExpressVPN，**付费**）+ 插了 CapSolver（付费打码）广告
- **能判断单条评价删除？** ❌ 不能，只批量抓评论内容
- **二开价值**：⭐⭐ 借鉴 review 抓取逻辑可以，但反爬是硬伤

## 七、变狗检测技术预研（业务核心，待实现）

> 这是本项目真正的"Know-how"，目前无现成开源实现，需自研。判定信号需组合：

### 7.1 Listing 变狗（页面失效）判定
- **HTTP 层**：返回 404；或 302 重定向到 `/errors/validateCaptcha`（被风控）
- **页面特征**：
  - `<title>` 含 `"Page Not Found"` / `"Dogpile"`
  - 含著名狗狗图（`<img src>` 路径含 `dogs`）
  - 含 `"Currently unavailable"` / `"This item is no longer available"`
  - 含 `"We have been notified that there is a problem"`
  - `#productTitle` 为空（产品标题抓不到）

### 7.2 评价"变狗"（评价被删）判定
- review section 缺失 / `"No customer reviews"`
- `total-review-count` 从 N → 0
- 单条评价 permalink 访问后找不到对应 review 节点

### 7.3 星级提取（已有现成选择器，来自 mohitrock850）
```python
星级文本:  span[data-hook='rating-out-of-text']
平均星:    i[data-hook='average-star-rating']
评价总数:  span[data-hook='total-review-count']
星级分布:  table#histogramTable tr
```

### 7.4 主要风险
- **反爬**：Amazon 强反爬，headless 易被识别 → 需 botasaurus 反检测 + 代理轮换 + 可能打码（付费）
- **限速**：几十~几百链接要加 `seconds_between_check` 限速，否则 IP 被封
- **Amazon 多站点**：`.com` / `.co.jp` / `.de` 等 DOM 结构略有差异，选择器要 fallback

# 需求重审：跳出"爬虫工具"思维

> 日期：2026-08-14（第三轮）
> 契机：前两轮一直顺着"找个无头浏览器方案"的思路走。重新眯眼看需求本质后，发现整个技术路线可能应该颠倒过来。

---

## 一、需求本质重析

用户表述："批量加评价链接 → 内置浏览器访问 → 判断评价在不在 / 变狗没 / 几星"

**剥掉实现细节，真实需求是三层：**

| 层 | 真实需求 | 频率 |
|----|---------|------|
| A | **我的 listing 活着吗**（变狗/下架/被风控） | 定时反复查 |
| B | **我的评分资产变化**（几星、评价总数增减、评价被删） | 定时反复查 |
| C | **单条评价 permalink 还在吗**（具体某条评价被平台删除） | 定期抽查 |

关键洞察：**"内置浏览器"不是需求，是用户猜的答案。** A 和 B 两层（占需求 80%）根本不需要自己开浏览器去撞 Amazon 反爬——亚马逊卖家生态里早有标准数据源。

---

## 二、被忽略的成熟方案：Keepa API

### 2.1 Keepa 是什么

亚马逊卖家人手一个的历史追价工具（浏览器插件 + 数据 API）。它**全天候抓取并存储所有 Amazon 产品的历史数据**，其中就包括：

- **RATING 历史序列**——星级随时间的变化 ⭐ 正是需求 B
- **COUNT_REVIEWS 历史序列**——评价总数随时间的变化 ⭐ 评价被删 = 序列骤降，正是需求 B
- 价格 / 库存 / Buy Box / 销量排名历史 ⭐ 间接覆盖需求 A（listing 变狗后数据流中断/标记 unavailable）

**已验证（Keepa 官方 API 文档 + Python 客户端文档）**：这些序列可通过 API 直接拉取，且有官方维护的 Python 客户端。

### 2.2 GitHub 生态（本轮新发现）

| 仓库 | Star | 说明 | 维护 |
|------|------|------|------|
| **akaszynski/keepa** | 311⭐ | Keepa 官方推荐的 Python 客户端，支持同步/异步/Pydantic 类型化输出，`pip install keepa` 即用 | 🟢 2026-08-04 |
| BWB03/keepa-adapter | 15⭐ | Keepa API 的 MCP Server + OpenClaw skill（可以做 AI 告警链路） | 🟢 2026-08-12 |

### 2.3 成本（关键决策信息，已核实）

Keepa API **没有免费档**，需要 Data Access 订阅：

| 档位 | 价格 | 额度 | 对本项目够不够 |
|------|------|------|--------------|
| Power User | **€19/月** | 1 token/分钟 ≈ 1440 次/天 | ✅ 几十~几百 ASIN 每天 N 轮查绰绰有余（批量查询一次可带 100 ASIN） |
| Business | €49/月 | 20 token/分钟 | 大规模才需要 |

**重要**：很多亚马逊卖家**本来就有 Keepa 付费订阅**（追价是日常刚需）。如果你已有，边际成本 = **零**。

### 2.4 Keepa 路线 vs 自建爬虫路线（灵魂对比）

| 维度 | 自建爬虫（前两轮方案） | Keepa API 路线 |
|------|----------------------|----------------|
| 反爬/封号风险 | 高（代理/指纹/打码全套伺候） | **零**（Keepa 替你扛了） |
| 历史数据 | ❌ 只有从部署日起的数据 | ✅ 直接拿到多年的 rating/review 历史 |
| 变狗判断 | 靠页面特征猜测 | 数据流中断/unavailable 标记，**还有历史可回溯** |
| 维护成本 | Amazon 改版就坏，选择器常修 | Keepa 官方维护，稳定 |
| 开发量 | 大（浏览器+反检测+判定+限速） | 小（调 API + 存库 + 看板） |
| 费用 | 名义免费，实际代理/打码可能花钱 | €19/月（已有订阅则免费） |
| 实时性 | 可做到分钟级 | 小时级更新（对监控够用） |

## 三、重新设计的架构（Keepa 为主，爬虫降级为兜底）

```
┌───────────────────────────────────────────────────────┐
│                  Streamlit 看板（宝塔）                 │
│      状态总览 / 星级趋势图 / 变狗告警 / 评价增减         │
├───────────────────────────────────────────────────────┤
│ 判定与告警（自研，纯 Python 逻辑）                      │
│  · 评分环比下降 > 阈值 → 告警                          │
│  · review count 骤降（评价被删）→ 告警                 │
│  · Keepa 数据流中断/unavailable → 疑似变狗             │
│  · 告警通道：看板红点 / 邮件 / 企微钉钉机器人           │
├───────────────────────┬───────────────────────────────┤
│  数据源 A（主力）      │  数据源 B（兜底/补充）          │
│  Keepa API            │  轻量浏览器（camoufox）         │
│  · listing 状态        │  · 单条评价 permalink 存活检测  │
│  · 星级历史            │    （Keepa 不覆盖单条评价）     │
│  · 评价总数历史        │  · Keepa 判为疑似变狗时的       │
│  · €19/月或已有订阅    │    二次确认（截图+规则）        │
├───────────────────────┴───────────────────────────────┤
│  SQLite（链接清单 + 每日快照 + 告警记录）               │
└───────────────────────────────────────────────────────┘
```

**三层需求的新答案：**

| 层 | 方案 | 需要浏览器吗 |
|----|------|------------|
| A listing 变狗 | **Keepa**（数据流中断/unavailable 标记 + 历史） | ❌ |
| B 星级/评价数变化 | **Keepa**（RATING + COUNT_REVIEWS 历史序列，还能画趋势图） | ❌ |
| C 单条评价 permalink | **自建轻量检测**（camoufox/patchright + 规则判定） | ✅ 唯一真需要浏览器的 |

爬虫从"主引擎"降级为"单条评价检测器 + 疑难确认"，工作量砍掉 70%。

## 四、决策矩阵：你该选哪条路

| 你的情况 | 推荐路线 |
|---------|---------|
| 已有 Keepa 付费订阅 / 愿意花 €19/月 | **Keepa 路线（本文档方案）**——最稳、有历史数据、开发量最小 |
| 一分钱不想花 + 接受一定失败率 | 自建爬虫路线（文档 01/02 方案：camoufox + 脚本判定） |
| 都要 | 混合：Keepa 管 A/B 层，爬虫只管 C 层（单条评价） |

> 提醒：如果你平时就在用 Keepa 插件追价，先去 keepa.com → Settings 看看自己的订阅是否已含 Data Access，很多卖家档位是包含少量 API 额度的。

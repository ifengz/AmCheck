# 服务器依赖清单修复指令（给宝塔 AI 执行）

## 问题一句话

`code/requirements.lock.txt` 停在 Streamlit 时代（44 行），**缺 nicegui /
fastapi / uvicorn / starlette / python-socketio / dingtalk-stream**；
而 `code/start.sh` 首次建 venv 时**优先装 lock 文件** ——
新机器跑 `start.sh` 会装完一堆 Streamlit 依赖后才在启动时
`ModuleNotFoundError: nicegui`。

生产**没有**受影响：`deploy/deploy.sh` 装的是 `requirements.txt`，
所以线上一直是好的；坏的只有「新机器 / 新克隆的首次初始化」这条路径。

## 三条硬约束（务必先读，否则会白干）

1. **不要修改 `/www/wwwroot/amcheck_git/` 下任何被 git 跟踪的文件。**
   `deploy.sh` 每次部署都执行 `git reset --hard origin/main`，
   服务器上的改动会被静默冲掉。所有修复必须走 git（本地改 → push）。
2. **不要动生产 `.venv`。** 所有验证都在 `/tmp` 下的一次性 venv 里做。
3. **不要重启服务、不要重跑 deploy.sh。** 本次只做「读 + 隔离验证」。

## 第一步：收集生产环境的真实依赖清单（只读，不改任何东西）

把下面整段原样交给宝塔 AI 执行：

```bash
cd /www/wwwroot/amcheck_git/code || { echo "路径不存在"; exit 1; }

echo "===== 1. 仓库当前版本 ====="
git -C /www/wwwroot/amcheck_git log --oneline -1
git -C /www/wwwroot/amcheck_git status --short

echo "===== 2. 生产 venv 的 Python 版本 ====="
./.venv/bin/python -V

echo "===== 3. 生产 venv 已装包数量 ====="
./.venv/bin/pip freeze | wc -l

echo "===== 4. 关键包在不在 ====="
./.venv/bin/pip freeze | grep -iE "^(nicegui|playwright|openpyxl|xlrd|dingtalk-stream|streamlit|pillow|fastapi|uvicorn|python-socketio)=" || echo "(有缺失)"

echo "===== 5. 核心模块能否导入 ====="
./.venv/bin/python -c "import nicegui, playwright, openpyxl, xlrd, dingtalk_stream, streamlit, PIL; print('全部可导入')" || echo "!! 有模块导入失败"

echo "===== 6. lock 文件现状 ====="
echo "行数: $(wc -l < requirements.lock.txt)"
git -C /www/wwwroot/amcheck_git ls-files code/requirements.lock.txt

echo "===== 7. 生产 venv 完整依赖清单(把这段原样回贴) ====="
./.venv/bin/pip freeze | sort -f
```

**需要回贴的内容**：第 2 节的 Python 版本 + 第 7 节的完整清单。

拿到之后我会用**服务器自己的 venv**重建 lock —— 那才是权威来源
（本地生成的是 macOS + Python 3.9 的 freeze，换到 Linux / 别的 Python
版本上可能有装不上的 pin，比如 numpy 2.0.2 就不支持 3.13）。

## 第二步：干净环境验证新 lock（等我把新 lock push 之后再执行）

```bash
rm -rf /tmp/amcheck_deps_check
git clone --depth 1 https://github.com/ifengz/AmCheck.git /tmp/amcheck_deps_check
cd /tmp/amcheck_deps_check/code
python3 -m venv .venv
./.venv/bin/pip install -q --upgrade pip
echo "--- 开始按 lock 安装(这是新机器的真实路径) ---"
if ./.venv/bin/pip install -r requirements.lock.txt; then
  echo "LOCK_INSTALL_OK"
else
  echo "LOCK_INSTALL_FAIL"
fi
./.venv/bin/python -c "import nicegui, playwright, openpyxl, PIL; print('IMPORT_OK')" \
  || echo "IMPORT_FAIL"
cd / && rm -rf /tmp/amcheck_deps_check
```

判据：出现 `LOCK_INSTALL_OK` + `IMPORT_OK` 即通过。
若失败，把报错原文回贴，我按服务器实际情况调 pin。

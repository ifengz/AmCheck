## 一、第二轮新发现的优秀仓库

### 🦊 1. daijiro/camoufox — 新一代反检测浏览器（本轮最大发现）

| 项 | 内容 |
|----|------|
| 地址 | https://github.com/daijiro/camoufox |
| Star | **11,087** ⭐ |
| 语言 | C++（Firefox 定制内核）+ 官方 Python 客户端 |
| 维护 | 🟢 最后 push 2026-08-12（本周还在更新） |
| License | 查 README 确认（Camoufox 基于 Firefox，MPL 系） |

**是什么**：基于 Firefox 深度魔改的反检测浏览器。指纹伪装在 **C++ 内核层**实现（不是 JS 注入层面），比 selenium-stealth / playwright-stealth 这种"补丁式"隐身高一个量级。

**为什么适合本项目**：
- 官方 Python API（`pip install -U camoufox[geoip]`），用法和 Playwright 几乎一样，学习成本低
- 指纹（UA/屏幕/WebGL/字体/时区）自动随机化且**内部一致性完整**——Amazon 的 JS 指纹检测很难识破
- 支持 headless 且 headless 也有完整指纹伪装（botasaurus 曾警告 headless 易被识别，camoufox 正好补这个短板）
- 可配合住宅代理 + geoip 自动匹配时区/语言

**与第一轮推荐的 botasaurus 对比**：
- botasaurus：一站式框架（并行/代理/captcha 全带），底层是 Chrome 系
- camoufox：专注"反检测浏览器"本身，Firefox 系，指纹伪装更深
- **结论：两者可组合（botasaurus 也支持外接浏览器），或直接 camoufox + Playwright 语法自己写**。纳米项目更推荐后者——依赖更少、更可控。

### 🛡️ 2. Kaliiiiiiiiii-Vinyzu/patchright — 隐身版 Playwright

| 项 | 内容 |
|----|------|
| 地址 | https://github.com/Kaliiiiiiiiii-Vinyzu/patchright |
| Star | **4,086** ⭐ |
| 语言 | TypeScript（同时有 Python 包 `patchright`） |
| 维护 | 🟢 2026-08-05 |

**是什么**：Playwright 的补丁版，修掉了 Playwright 所有的自动化泄漏点（runtime enable、navigator.webdriver、CDP 痕迹等）。**API 与 Playwright 100% 兼容**——如果你会 Playwright，把 `from playwright.sync_api import sync_playwright` 改成 `from patchright.sync_api import sync_playwright` 就完成"隐身升级"。

**定位**：比 camoufox 轻（还是 Chromium 内核，指纹不如 camoufox 深），但**迁移成本为零**。适合"先跑通，被检测了再升级 camoufox"的渐进路线。

### 🤖 3. browser-use — AI 浏览器代理（109k⭐，但要辩证看）

| 项 | 内容 |
|----|------|
| 地址 | https://github.com/browser-use/browser-use |
| Star | **109,145** ⭐ |
| 维护 | 🟢 2026-08-13（每日更新） |

**是什么**：让 LLM（GPT/Claude/GLM）看浏览器截图 + 页面结构，自己决定点什么、填什么。自然语言驱动：「去这个 Amazon 链接看看评价还在不在，几星」。

**对本项目的适用性分析**（重要，别被 109k star 冲昏头）：

| 维度 | 评价 |
|------|------|
| 优势 | 无需写选择器，页面改版也不怕；天然能"理解"变狗页/验证码页；中文指令直接下 |
| 劣势 | ① **每查一条链接都要烧 LLM token**，几百条 × 每天多次 = 成本失控；② 慢（每步都要模型推理）；③ 结果**不确定**——同一页面两次判断可能不同；④ 反检测能力弱于 camoufox（本身不带指纹伪装） |

**结论**：❌ 不适合做主引擎，✅ 适合做「疑难杂症兜底」（详见第三节混合架构）。你本地装了它的 MCP（我看到了 `browser-use` MCP 配置），调试期拿它人肉验证判定逻辑很方便。

### 4. saifyxpro/HeadlessX — 自托管反检测浏览器平台（2.2k⭐）

camoufox 的封装，带 API 的自托管浏览器自动化平台，宣称 0% 检测率。适合团队化，纳米项目直接用 camoufox 本体即可，不必多一层。**备选记录**。

### 5. bytedance/UI-TARS-desktop（38.6k⭐）

字节的桌面级 GUI 操作 Agent。杀鸡用牛刀，排除，仅记录。

### 6. firecrawl（167k⭐）

自托管网页转 Markdown 服务，LLM 向。对「结构化状态判断」无优势，且自托管较重。排除。

### 7. 卖家向监控（amazon-seller-monitor / asin-checker 等）

全部 0–1⭐，要么是 ScraperAPI 引流文档，要么是废弃玩具。**再次确认：没有任何成熟开源项目做「评价存活/变狗」检测。**

## 三、核心问题：查看评价，用 AI 还是脚本？

**答案：脚本为主（80% 场景），AI 做兜底确认（20% 疑难场景）。不要全 AI，也不要纯脚本。**

### 3.1 为什么主体必须是脚本（确定性判定）

你检测的是**客观事实**，不是主观理解：

| 检测项 | 脚本判定方式 | 可靠性 |
|--------|-------------|--------|
| 页面是否变狗 | HTTP 404 / title 含 "Page Not Found" / 狗图 URL 含 `dogs` | 100% 确定 |
| 是否被风控 | 重定向到 `/errors/validateCaptcha` | 100% 确定 |
| 评价是否还在 | `span[data-hook='total-review-count']` 存在且 > 0 | 100% 确定 |
| 几星 | `span[data-hook='rating-out-of-text']` / `aria-label` | 100% 确定 |

脚本的优势：
- **快**：毫秒级判定，几百条链接几分钟跑完
- **免费**：零 token 消耗
- **可复现**：同一页面永远同一个结论，可写进报告、可审计
- **可监控**：出了错你知道错在哪一行

### 3.2 AI 的正确用法：兜底 + 辅助（不是主引擎）

三种场景 AI 有不可替代的价值：

1. **页面异常兜底**：脚本判定为"疑似变狗"（title 为空/结构不认识）时，把**截图丢给视觉模型**（GLM-4V / GPT-5V）问「这是 Amazon 正常产品页、变狗页、验证码页还是别的？」——一次性确认，避免误报。每条只花一次视觉调用，成本可控。
2. **单条评价 permalink 的语义匹配**：判断「某条特定评价是否还在」需要确认页面上的 review 是不是原来那条（标题/作者/内容匹配），模糊匹配用 LLM 比正则稳。
3. **页面改版自愈**：Amazon 改版导致选择器失效时，AI 可以临时顶上 + 告警提醒你更新选择器。

### 3.3 全 AI 方案为什么不行（browser-use 直接跑）

- **成本**：几百链接 × 定时监控 × 每条多步推理 = 每月几十~几百美元 token，而脚本 = 0
- **速度**：AI 每条 10–30 秒 vs 脚本每条 1–3 秒
- **稳定性**：LLM 会幻觉，可能把正常页判成变狗——监控工具最忌讳误报
- **反爬**：browser-use 不带深度指纹伪装，在 Amazon 面前反而比 camoufox 脆弱

### 3.4 推荐的混合架构（写进未来实现）

```python
def check_url(url) -> Result:
    page = camoufox_open(url)                    # 反检测浏览器
    verdict = rule_based_check(page)             # ① 脚本规则先行（快、准、免费）
    if verdict.confident:                        # ② 明确结论直接返回
        return verdict
    return ai_verify(page.screenshot())          # ③ 拿不准才调视觉模型兜底
```

## 五、两轮调研总结论

1. **现成方案**：依旧为零。「批量评价链接 → 存活/变狗/星级」在开源界是空白，第二轮从 AI Agent、反检测、卖家工具三个方向验证了这个判断。
2. **最优技术组合**（纳米项目版）：
   **Python + Streamlit（看板）+ camoufox（反检测浏览器）+ 脚本规则判定（主）+ GLM-4V 视觉兜底（辅）+ SQLite（存历史）**，宝塔 Python 项目管理器部署。
3. **AI vs 脚本**：脚本判事实，AI 判疑难。架构上一行 `if not confident: ai_verify()` 就够。
4. **所有前置调研已完成**，可以随时进入「搭原型」阶段。
